Metering unavailable — the mixer's native connection was refused. Faders, mutes and scene recall are working normally.

The scale is generated from the driver's fader law, not hard-coded. §5.5 already has the driver publishing a position–to–dB table so the browser can place the thumb at frame rate; the printed legend comes from the same table. Which points are labelled is a driver property too, because desks print different scales:

Allen & Heath CQ +10 +5 0 −5 −10 −20 −30 −40 −∞
unity at 76.6% of travel
A different desk +10 0 −10 −20 −30 −50 −∞
unity elsewhere, different taper

Swap the mixer and the legend follows, because it was never ours to define. Hard-coding A&H's law would have made the scale confidently wrong on any other hardware — worse than having no scale.

0 dB detents. Within 1.5 dB the fader holds exactly at unity and the cap picks up an amber ring; breaking out takes a deliberate further push rather than a nudge. This matters far more on a touchscreen than a mouse, and unity is the position an operator returns to most.

The meter gradient changes colour exactly at the printed marks. Green below −10, amber to 0, red above. The meter reads the same whether you look at the colour or the scale.

Stereo channels get two meters. ST1 and ST2 arrive as separate left and right records, so a summed meter would hide the failure that matters most: one side dead means a cable or source fault, and a single bar reading “signal present” sends you looking in the wrong place.

When metering is unavailable the bar is absent, not empty, and the fader re-centres. An empty meter track reads as silence, which would be a lie.
